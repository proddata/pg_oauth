# Initial security-review traceability

This matrix records evidence for the Milestone 1 threat model and the initial
security-review criteria in `FEATURES.md`. It is an audit aid, not a substitute
for the specification. A row is **covered** only when an enforcing production
boundary and an exact accepting and rejecting test exist. **Partial** means
useful enforcement or tests exist but the stated requirement is not completely
proved. **Deferred** identifies an acknowledged non-goal rather than missing
Milestone 1 behavior.

Test names below are executable names for C tests and pytest function names for
integration tests. All paths were checked when this matrix was written.

|---|---|---|---|---|

| Valid principal assumes an unrelated PostgreSQL role | PostgreSQL applies exact identity matching or `map=`/`pg_ident.conf`; with delegation, `shared/policy.c` requires a configured `role_claim` and `shared/claims.c` checks the requested role | `test_valid_token_uses_normal_pg_ident_mapping` accepts the mapped role; `test_direct_identity_and_delegated_roles` accepts exact identity and authorized scalar/array roles | `test_direct_identity_and_delegated_roles` denies each case for its own reason, read from the server log: a role the validator accepted but PostgreSQL refused, `claims=unauthorized_role`, `claims=invalid_roles` for a duplicate, `code=policy_delegation_mismatch` for either delegation setting alone, and `no pg_hba.conf entry` for an HBA-capped role. `test_malformed_and_oversized_role_claims_are_denied_as_invalid_roles` denies empty, wrong-typed, control-character, absent and over-bound role claims (including a valid role next to a malformed one) and accepts the 64-role and 63-byte boundaries. `tests/policy_test.c` rejects mismatched delegation settings | **Covered** |
| Ambiguous or mutable identity | `shared/claims.c` requires `sub` and validates the selected claim; `shared/identity.c` bounds and copies it directly; `shared/identity_text.h` is the single text rule (controls, malformed UTF-8, and invisible, line-breaking and bidirectional characters); default `sub` is built in `validator/config.c` | `tests/identity_test.c`: direct identity; `test_valid_token_uses_normal_pg_ident_mapping`: exact subject maps | `tests/claims_test.c`: missing, wrong-type, control-character, invisible-character and bidi-override subject and identity; `tests/identity_test.c`: empty, oversized and invalid input, and each rejected code point range on both edges with its legitimate neighbours accepted; `test_identities_with_invisible_or_reordering_characters_are_denied`: a role whose name contains such a character is unreachable even with an exactly matching token | **Partial**. | Malicious or compromised discovery/JWKS | `shared/metadata.c`, `shared/http_transport.c`, `shared/jwks.c`, and exact issuer/host policies in `shared/issuer_key.c` | `tests/metadata_test.c`: valid exact metadata; `tests/http_transport_test.c`: bounded trusted response; `tests/jwks_test.c`: valid signing keys | Unit rejection cases plus `tests/integration/test_oauth.py::test_local_idp_transport_failures_deny_and_recover`, which rejects hostile discovery/JWKS responses and proves recovery | **Covered** for hostile input and transport behavior. A correctly trusted but compromised issuer remains outside offline validation's protection. |
| SSRF, redirects, oversized responses, slow endpoints, and cache poisoning | `shared/http_transport.c`, `shared/http_freshness.c`, `shared/cache_key.c`, and policy-separated shared cache | `tests/http_transport_test.c`: allowed host, trusted TLS, JSON response and freshness headers; `tests/cache_key_test.c`: complete canonical policy key | Component adversarial cases; callback transport failures/recovery in `test_local_idp_transport_failures_deny_and_recover`; trust-policy reload separation in `test_reload_separates_trust_policy_cache_entries` | **Covered** |
| Empty or incorrectly interpreted scopes | `shared/policy.c` rejects empty required scopes; `shared/claims.c`: strict `scope` string/array parsing and require-all comparison | `tests/claims_test.c`: valid scope string and array; `test_valid_token_uses_normal_pg_ident_mapping`: valid required scope | `tests/claims_test.c`: missing/insufficient/wrong syntax/duplicate scope and implicit `scp`; integration test rejects insufficient scope; `tests/policy_test.c` rejects empty required scopes | **Covered** |
| Provider-specific format applied to wrong issuer | `shared/policy.c` accepts only policy `default`; `shared/claims.c` rejects implicit `scp`; exact issuer validation is in `shared/claims.c` and `shared/metadata.c` | `tests/policy_test.c`: default policy; `tests/claims_test.c`: exact configured issuer | `tests/policy_test.c`: unknown policy; `tests/claims_test.c`: `scp` rejected and trailing-slash issuer mismatch | **Covered for current policy**. | Token, signature, secret, or sensitive claims disclosed in diagnostics | Stable error-code functions throughout `src/`; callback logging in `validator/pg_oauth_validator.c` emits codes rather than token bytes | Successful real OAuth connection in `test_valid_token_uses_normal_pg_ident_mapping`; each unit boundary checks stable codes | `tests/integration/test_security_logging.py` uses distinct raw-token, signature, private-claim, response-body, and complete-token sentinels across normal and rejection paths while requiring stable diagnostic codes | **Covered** for validator-controlled diagnostics. | DoS through repeated fetches or expensive JWT work | Token/document/key/count/time bounds in `shared/jwt_envelope.c`, `shared/http_transport.c`, `shared/metadata.c`, `shared/jwks.c`; refresh cooldown in `shared/cache_state.c`/`shared/shared_cache.c` | Boundary tests accept inputs within limits; robustness integration keeps valid cached authentication responsive during hostile load | Oversize/complexity unit cases; unknown-`kid` suppression; `tests/integration/test_robustness.py` exhausts all cache slots and applies bounded concurrent excess and mixed hostile/valid connection bursts | **Covered** by deterministic CI smoke bounds; longer performance profiling remains operational work, not an authorization acceptance gap. |

## Initial acceptance criteria

| Criterion from `FEATURES.md` | Exact evidence | Status / follow-up |
|---|---|---|
| Correctly signed token for another audience is rejected | `tests/claims_test.c` audience rejection cases; audience-reload rejection in `test_valid_token_uses_normal_pg_ident_mapping`; Keycloak wrong-audience rejection | **Covered** |
| Trusted issuer's ID token is rejected | `tests/validator_test.c` ID-token case; Keycloak ID-token connection rejection | **Covered** |
| Missing `iss`, `sub`, `exp`, `aud`, or configured identity is rejected | Enforcement is in `shared/claims.c`; `tests/claims_test.c` has focused missing-claim cases for each mandatory claim and custom identity. | **Covered** |
| Wrong-type and malformed security-sensitive claims are rejected | `tests/claims_test.c` covers wrong-type issuer, audience, temporal, scope, and default/custom identity values; duplicate claims are rejected by `tests/jwt_envelope_test.c`. | **Covered** |
| Only administrator-allowed asymmetric algorithms and valid keys are accepted | `tests/policy_test.c`, `tests/jwt_envelope_test.c`, `tests/jwks_test.c`, and `tests/signature_test.c` positive and negative cases | **Covered** |
| Rotated keys are adopted without attacker-driven refresh storms | `test_local_idp_rotation_outage_and_recovery` plus `test_unknown_kid_refresh_is_suppressed_across_backends`; cache/issuer-key unit tests | **Covered** |
| Valid principal cannot assume an unrelated role | Direct, usermap, and delegated acceptance and denial in `test_valid_token_uses_normal_pg_ident_mapping` and `test_direct_identity_and_delegated_roles` | **Covered** |
| Delegation requires both validator and HBA policy | `tests/policy_test.c` and `test_direct_identity_and_delegated_roles` reject either setting alone (asserting `code=policy_delegation_mismatch`), `test_malformed_and_oversized_role_claims_are_denied_as_invalid_roles` rejects malformed role claims, and the HBA-capped case asserts the HBA refusal | **Covered** |
| No token or secret appears in normal, debug, or error logs | Multiple integration tests plus `test_security_logging.py` assert distinct token, signature, private-claim, and provider-response sentinels are absent while stable protected diagnostics remain present. Configuration explicitly forbids storing secrets in GUCs because PostgreSQL core may log changed values. | **Covered** for validator-controlled values and diagnostics. |
| Network failures and cache behavior are deterministic and documented | Local rotation/outage/freshness/recovery, hostile transport, unknown-`kid`, and reload-separation integration tests; cache unit tests; `docs/operations.md` and ADR 0002 | **Covered** |
| Negative tests cover the documented threat model and run in CI | `.github/workflows/ci.yml` runs `test-pg18` and `test-pg19`, which include `verify` and `integrationcheck` | **Covered** for the active offline suite. Keycloak interoperability is intentionally opt-in and remains a separate release gate. |
| PostgreSQL integration tests exercise real connections over TLS | Existing OAuth tests use TLS; `tests/integration/test_tls.py` proves libpq `verify-full` success and rejects PostgreSQL/provider hostname mismatch, untrusted CA, and deterministic already-expired leaf certificates on both majors. | **Covered**. |

## PAM module (experimental) and the ADR 0009 release gate

[ADR 0009](../adr/0009-pam-cache-and-module-isolation.md) lists what must be
proved before a production PAM release. PAM validates tokens with the same
sources as the native validator, so the rows above apply to it; the tests below
run the real module through libpam. The CI jobs `PAM module / PostgreSQL 15` to
`19` run `tests/pam`, and the 18 and 19 jobs also run `tests/pam_both`. Status
uses the same terms as above. A **Gap** row blocks a production PAM release; it
does not block a prerelease, whose notes must state it.

| ADR 0009 gate item | Evidence | Status and remaining gap |
|---|---|---|
| Cross-backend cooldown and refresh suppression | `tests/pam/test_pam_validation.py`: `test_cache_is_shared_across_backends`, `test_unknown_key_refresh_is_suppressed_across_backends`, `test_concurrent_cold_logins_share_one_refresh`, `test_unknown_key_flood_on_a_cold_cache_is_bounded` | **Covered** on PostgreSQL 15 to 19 |
| Policy and reload isolation | `test_policy_change_never_reuses_other_policy_cache`, `test_policy_changes_apply_to_later_connections_only`, `test_cache_uses_its_own_namespace`, `test_oversized_cache_key_denies_instead_of_skipping_the_cache`; `tests/pam_both/test_both_modules.py::test_caches_are_separate` | **Covered** |
| Capacity isolation | `tests/pam_both/test_both_modules.py::test_a_full_cache_in_one_module_does_not_affect_the_other` (both directions, both caches at the minimum of eight entries): one module's cache is filled until it denies a new policy, then the other still serves its warm entry with no provider request and still caches new policies. Giving PAM the validator's segment name makes it fail | **Covered** on PostgreSQL 18 and 19, the majors where both modules can be installed |
| Owner failure, flood, outage and recovery | Outage: `test_cold_cache_outage_denies_and_recovers`, `test_fresh_cache_survives_a_provider_outage`. Flood: `test_unknown_key_refresh_is_suppressed_across_backends`, `test_unknown_key_flood_on_a_cold_cache_is_bounded`. Owner aborted: `tests/pam/test_pam_interrupt.py` (authentication timeout and fast shutdown interrupt a provider fetch or key refresh; `test_authentication_timeout_interrupts_provider_fetch` and `..._key_refresh` assert later logins are not poisoned), and for the native validator `tests/integration/test_robustness.py::test_an_owner_aborted_mid_fetch_does_not_block_later_logins`. Owner hung: `test_a_hung_refresh_owner_fails_waiters_closed_and_blocks_nothing_else` stops the refreshing backend with SIGSTOP, requires a waiting login to be denied within the configured wait and an unrelated entry to stay usable, then releases the owner and requires the entry to recover. Slow name resolution: `test_slow_name_resolution_does_not_hold_an_unauthenticated_backend` uses a resolver shim in the server process (it asserts the shim was used) and requires the login to end under the authentication timeout, or under the fetch's own connect timeout when none is set, with the server healthy afterwards | **Covered**. Limits: a hard-killed backend makes the postmaster restart and reinitialize shared memory (PostgreSQL's design, not testable in isolation). The abandoned resolver thread is covered at the transport level (`tests/http_transport_driver.py`); inside a server the backend exits when authentication fails, so the case of a resolver thread outliving the loaded module is not reproduced there |
| Bounded lock contention | `tests/pam/test_pam_interrupt.py::test_cache_hits_are_not_delayed_by_a_refresh_in_flight`: while one login owns a slow refresh, five sequential and eight concurrent cache-hit logins for another policy finish within two seconds and the slow login is still running afterwards, so the shared lock is not held across provider I/O. Holding the lock for 400 ms in the lookup makes it fail. The cache logic is shared with the native validator, whose hostile-load test is `tests/integration/test_robustness.py` | **Covered** for the property the gate names (no lock held across provider I/O, hits not delayed by a refresh). It is a functional bound, not a throughput benchmark: every cache operation takes one exclusive lock |
| Installed paths, permissions and SELinux enforcement | RPM subpackage build and installed-module suite, and `tests/pam/selinux_check.py` (allowed and denied cycles in the SELinux enforcing VM, `scripts/ci/test-selinux-guest.sh`); see [RPM platforms](../rpm-platforms.md) | **Covered** for the PostgreSQL 18 RPM on Fedora 43, Fedora 44 and Rocky Linux 10; no other RPM majors or distributions exist. Separately from RPMs, the PostgreSQL 18 and 19 release archives also carry the module, checked by the staged-install check in `make packagecheck` and the release build. The PAM suite was run against the module extracted from each archive by hand when it was added, and that step is a pre-publication instruction in `docs/release-readiness.md`, not an automated CI job |
| OAuth-only, PAM-only and both-installed deployments | `pam-check-pg15` to `19`; `tests/pam_both/test_both_modules.py::test_each_rule_uses_exactly_one_method` and `test_caches_are_separate`; `make check-modules-disjoint` | **Covered**; a single process loading both modules is deliberately not tested (ADR 0009) |
| Removing or failing either module leaves the other unchanged | `test_breaking_pam_leaves_oauth_working`, `test_breaking_oauth_leaves_pam_working`, `test_removing_either_module_leaves_the_other_working` | **Covered** |
| PostgreSQL 15 and 16: a preloaded module and the libpam-loaded module share one cache; a missing preload denies | `test_missing_preload_denies_before_postgresql_17`; the cache tests above run with the module preloaded on 15 and 16; `tests/pam/test_pam_copies.py::test_a_module_copy_the_server_did_not_preload_never_runs_a_private_cache` on every major: a symlink to the preloaded file shares its cache (no extra provider request), and a byte-identical copy at another path is denied, before any provider request, on 15 and 16, and shares the named segment on 17 and later. Letting an unpreloaded copy allocate a private cache, or giving each process its own segment, makes it fail | **Covered**. The single copy is shown by behavior (provider request counts and denial), not by inspecting shared memory, and relies on the C library treating a path that resolves to the same file as the same loaded object |
